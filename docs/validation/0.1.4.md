# 0.1.4 本地验收记录

日期：2026-10-17；平台：Windows x86_64；源码分支：codex/0.1.4。版本尚未打 tag 或发布；远程 PR CI 单独记录，不以本地通过替代。

## 工具链与构建

- Rust：rustc 1.98.1 (48a229cea 2026-09-01)；VS2022 Build Tools 的 vcvars64 环境。
- Zig：固定 0.13.0；生成型/静态 guest 和 BusyBox 均重建。早期使用本机 0.17 开发版的探索结果不作为最终证据。
- BusyBox：1.36.1，上游源 SHA-256 固定在构建脚本，gzip/gunzip 及未对齐访问补丁已应用，保留 sanitizer。
- 动态 musl：保留仓库提供的真实动态 hello 与 musl 1.2.5 loader fixture，构建和验收核对固定 SHA-256 与 `PT_INTERP`，并在 auto/VEH/island 模式核对加载日志和输出。Zig 0.13.0 内置 musl 的 `-dynamic` 产物实际为静态 PIE，不能作为动态覆盖。

## 门禁

统一入口为 `scripts/quality.ps1 -Package`；此前已用固定 Zig 执行 `tools/build-busybox.sh`。CI 从源码通过 `quality.ps1 -BuildBusybox -Package` 重建生成型/静态 guest 和 BusyBox，并校验动态 fixture。

| 门禁 | 本地结果 |
| --- | --- |
| cargo fmt --all -- --check | 通过 |
| cargo clippy --workspace --all-targets -- -D warnings | 通过 |
| cargo test --workspace | 105 tests 通过，含 host source gate |
| release 二进制完整 acceptance | 78 checks 通过 |
| ZIP 解压到源码外，执行包内同一 acceptance | 78 checks 通过 |

验收包含 auto/VEH 各三次的线程、信号、socket 和 epoll guest，专用 island 汇编用例实际安装岛页并执行 fork/并发 clone，BusyBox gzip/tar 数据校验、实际 wget 下载 SHA-256 与 404/截断失败、nc 双向 TCP/EOF，以及既有文件/动态 musl/root/fork/exec 回归。

所有 guest 有进程级 deadline，网络服务绑定动态 loopback 端口。软 TLS 通过不代表硬件 FS 或性能结论。未测试任意指令抢占、AVX/完整 XSAVE、网络 fd fork 继承或非 Windows 运行。

## 可检查产物

- `release/vela-v0.1.4-windows-x64.zip` 和 `.zip.sha256`。
- `release/validation/acceptance.json`、原始 stdout/stderr、BusyBox 构建日志。
- `release/package-validation/acceptance.json`，执行文件与所有 guest 的 SHA-256。
- `release/package.json` 记录源码 commit/dirty 状态、ZIP 路径、大小、hash 和对应验收报告；最终提交后重新生成。
- `release/quality.log` 与 `release/quality-run.log` 保存统一入口输出。

具体产物 hash 以随产物生成的 JSON/SHA-256 文件为准，避免文档静态 hash 与最终重打包漂移。
